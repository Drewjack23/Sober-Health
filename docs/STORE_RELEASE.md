# Store release runbook

The repository is configured for EAS production builds for iOS and Android. Code readiness does not replace credentialed store setup, real-device testing, or legal review.

## Accounts and identifiers

- Apple Developer Program membership and App Store Connect access.
- Google Play Console developer account and Play App Signing.
- Expo account with this project linked by running `npx eas-cli init`.
- iOS bundle ID: `com.soberplus.health`.
- Android package: `com.soberplus.health`.
- Confirm the identifiers are available before the first signed build; they cannot be casually changed after release.

## Production services

1. Create the production Supabase project.
2. Apply `supabase/migrations/001_initial_schema.sql`.
3. Deploy `supabase/functions/delete-account` and configure its server-only secrets.
4. Configure email verification, reset redirects, rate limits, and production email templates.
5. Set `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_SUPPORT_EMAIL`, and `EXPO_PUBLIC_PUBLIC_SITE_URL` as EAS production environment variables.
6. Deploy the web build so `/privacy-policy`, `/terms`, and `/app-support` have permanent HTTPS URLs.

Never place a Supabase service-role key in an `EXPO_PUBLIC_` variable or client build.

## Quality gate

```bash
npm ci
npm run doctor
npm run lint
npm run typecheck
npm test
npm run bundle:ios
npm run bundle:android
```

Test signed preview builds on, at minimum:

- A small supported iPhone and a current large iPhone.
- An iPad because `supportsTablet` is enabled.
- A small Android phone, a current Android phone, and a tablet.
- VoiceOver and TalkBack, increased text sizes, reduced motion, dark mode, offline/reconnect, interrupted sign-in, password reset, export, and account deletion.
- Every external emergency/support link in each release country.

## Build and submit

```bash
npx eas-cli login
npx eas-cli init
npm run eas:build:ios
npm run eas:build:android
npm run eas:submit:ios
npm run eas:submit:android
```

Use TestFlight and a Google Play internal-testing track before production review. EAS remotely increments native build numbers; the customer-facing version remains in `app.json`.

## App Store Connect

- Use the metadata drafts under `store/metadata/en-US`.
- Set the primary category to Health & Fitness; consider Lifestyle as secondary.
- Set the privacy-policy URL to `https://YOUR_DOMAIN/privacy-policy`.
- Set the support URL to `https://YOUR_DOMAIN/app-support`.
- Complete the privacy nutrition label using `docs/STORE_PRIVACY_DISCLOSURES.md`.
- Provide required iPhone and iPad screenshots from signed builds.
- Complete age rating, content rights, export compliance, review contact, and availability.
- State that non-exempt encryption is not used; `ITSAppUsesNonExemptEncryption` is configured as false.

## Google Play Console

- Upload the `.aab` generated by the production Android profile.
- Enable Play App Signing.
- Set the app category to Health & Fitness.
- Complete Data Safety using `docs/STORE_PRIVACY_DISCLOSURES.md`.
- Add the privacy-policy and support URLs.
- Complete content rating, target audience (adults), app access, ads declaration, health-app declaration, and testing requirements.
- Add phone and tablet screenshots, feature graphic, and high-resolution icon.

Expo SDK 57 targets Android API 36 and iOS 16.4+, satisfying the platform SDK baselines in effect on August 7, 2026. Recheck both stores immediately before every submission.
